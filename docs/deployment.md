# Развёртывание

Документ описывает целевую схему; команды и файлы появятся на этапах 1 и 10.

## 1. Схема

Один сервер на салон (или сеть филиалов), Docker Compose:

| Сервис | Образ | Назначение |
|---|---|---|
| `nginx` | nginx | HTTPS (Let's Encrypt), прокси на api и frontend, лимиты частоты, ограничение размера тела |
| `api` | backend | FastAPI (uvicorn, 2–4 воркера), миграции при старте отдельной командой |
| `worker` | backend | Celery worker: входящие сообщения, ИИ, отправка, уведомления |
| `beat` | backend | Celery beat: расписание напоминаний, восстановление событий |
| `frontend` | frontend | Next.js (production build) |
| `postgres` | postgres:16 | Данные; том на диске сервера |
| `redis` | redis:7 | Брокер Celery, лимиты частоты; без хранения важных данных |

Минимальный сервер: 2 vCPU, 4 ГБ RAM, 40 ГБ SSD.

Для салонов из России сервер с базой данных размещается в России (локализация ПДн,
см. [risks.md](risks.md), риск R1).

## 2. Требования к сети

- Домен с записью A на сервер; HTTPS на 443 обязателен для вебхука Telegram.
- Исходящий доступ к `api.telegram.org`, `api.vk.com` и API выбранного LLM-провайдера.
- Снаружи открыты только 80 (редирект и выпуск сертификата) и 443.
- PostgreSQL и Redis доступны только внутри сети Docker.

## 3. Секреты и настройки

Переменные окружения из `.env` (на сервере, права `600`, не в git):

| Переменная | Назначение |
|---|---|
| `DATABASE_URL`, `REDIS_URL` | Подключения |
| `JWT_SECRET` | Подпись access-токенов (≥ 32 случайных байт) |
| `ENCRYPTION_KEY` | Ключ Fernet для токенов ботов в БД |
| `PUBLIC_BASE_URL` | `https://<домен>` — для адресов вебхуков |
| `LLM_PROVIDER`, `LLM_MODEL`, `LLM_EFFORT`, ключ провайдера | ИИ |
| `LLM_DAILY_BUDGET_USD` | Дневной лимит расходов на ИИ |
| `LOG_LEVEL` | Уровень логов |

Токены Telegram и VK в `.env` не хранятся: владелец вводит их в панели, они
шифруются ключом `ENCRYPTION_KEY`. Потеря этого ключа = повторный ввод токенов.

## 4. Обновление

1. `git pull` нужной версии (тег).
2. `docker compose build`.
3. `docker compose run --rm api alembic upgrade head`.
4. `docker compose up -d`.

Входящие сообщения во время перезапуска не теряются: Telegram и VK повторяют доставку,
а принятые события лежат в БД до обработки.

## 5. Резервное копирование

- Ежедневно `pg_dump` в сжатый файл, шифрование, отправка во внешнее хранилище
  (в той же юрисдикции, что и сервер); хранение — 14 ежедневных и 8 еженедельных копий.
- Раз в месяц — проверка восстановления на отдельной машине.
- Redis не резервируется: потеря очереди восстанавливается из `inbound_events` и
  `notifications`.

## 6. Мониторинг и логи

- Логи контейнеров в JSON, ротация Docker; без токенов, паролей и текстов сообщений.
- `GET /ready` раз в минуту из внешнего сервиса проверки доступности.
- Оповещения владельцу/разработчику: интеграция канала вернула ошибку, очередь растёт,
  LLM недоступен, превышен бюджет, не выполнилось резервное копирование.
- Сервис сбора ошибок — самостоятельно размещаемый (например, GlitchTip), чтобы ПДн
  из стека ошибок не уходили стороннему сервису.
