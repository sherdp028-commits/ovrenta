# Интеграции Telegram и ВКонтакте

> Официальную документацию Telegram Bot API и VK API из среды разработки открыть не
> удалось: сеть песочницы не пускает к `core.telegram.org` и `dev.vk.com`. Параметры
> ниже даны по известной мне документации. Перед реализацией каждого канала (этапы 3
> и 7) их нужно сверить с официальными страницами. Места, где сверка особенно важна,
> помечены «⚠ проверить».

## 1. Общий слой каналов

Бизнес-логика не знает, из какого канала пришло сообщение. Адаптер канала переводит
событие в общий формат, Conversation Manager работает только с ним.

```python
# app/channels/types.py (эскиз)
class InboundMessage(BaseModel):
    integration_id: UUID
    channel: Literal["telegram", "vk"]
    external_event_id: str        # update_id / event_id
    external_user_id: str         # кто написал
    external_chat_id: str         # куда отвечать (chat_id / peer_id)
    external_message_id: str | None
    text: str | None
    action: ButtonAction | None   # нажата кнопка: {"kind": "confirm", "id": "…"}
    contact_phone: str | None     # клиент поделился своим номером (только Telegram)
    has_unsupported_content: bool # фото, стикер, голосовое
    user_display_name: str | None
    user_username: str | None
    is_private_chat: bool
    sent_at: datetime

class Button(BaseModel):
    text: str
    action: ButtonAction          # кодируется адаптером в callback_data / payload

class Keyboard(BaseModel):
    rows: list[list[Button]]
    inline: bool = True

class OutboundMessage(BaseModel):
    integration_id: UUID
    external_chat_id: str
    text: str
    keyboard: Keyboard | None = None
    request_phone: bool = False   # показать кнопку «Поделиться номером»

class ChannelAdapter(Protocol):
    def parse_event(self, payload: dict) -> InboundMessage | None: ...
    def send(self, message: OutboundMessage) -> SendResult: ...
    def acknowledge_action(self, inbound: InboundMessage, text: str | None = None) -> None: ...
    def show_typing(self, external_chat_id: str) -> None: ...
```

**Кнопки.** `ButtonAction` — короткая структура `{kind, id}`, например
`{"kind": "confirm", "id": "<pending_action_id>"}` или `{"kind": "slot", "id": "<n>"}`.
Адаптер кодирует её компактно (`c:<uuid>` — 38 байт), чтобы уложиться в лимит Telegram
64 байта. Всё остальное (что именно подтверждается) хранится в БД, а не в кнопке:
кнопке нельзя доверять больше, чем ID.

**Отправка — через Channel Gateway** (`app/channels/gateway.py`):

1. Длинный текст делится на части (Telegram — 4096 символов, VK — 4096; режем по
   абзацам с запасом).
2. Сообщение сначала сохраняется в `messages` (`delivery_status = pending`), потом
   отправляется. Результат пишется в ту же строку.
3. Временные ошибки (сеть, 5xx, 429) → Celery повторяет 3 раза с паузой 2, 10, 60 с
   (при 429 — не раньше `retry_after`). Постоянные ошибки (пользователь заблокировал
   бота, чат не найден) → `failed`, канал клиента помечается `is_reachable = false`,
   повторов нет.
4. Ограничение частоты на интеграцию в Redis (токен-бакет): защищает от бана при
   рассылках и напоминаниях.

## 2. Telegram

### 2.1. Подключение бота

1. Владелец создаёт бота у @BotFather и вставляет токен в панели
   (`POST /api/v1/integrations/telegram`).
2. Backend вызывает `getMe` (проверка токена), генерирует секрет вебхука (32 случайных
   байта → 43 символа base64url) и вызывает `setWebhook`:
   - `url`: `https://<домен>/webhooks/telegram/<integration_id>`;
   - `secret_token`: сгенерированный секрет (⚠ проверить: 1–256 символов,
     допустимы `A-Z a-z 0-9 _ -`);
   - `allowed_updates`: `["message", "callback_query"]`;
   - `drop_pending_updates`: `true` при первом подключении;
   - `max_connections`: 10.
3. Backend вызывает `setMyCommands` с командами из ТЗ и сохраняет интеграцию: токен —
   зашифрованным, секрет — только хешем.

Требования Telegram к вебхуку (⚠ проверить): HTTPS с действительным сертификатом,
порты 443, 80, 88 или 8443. Мы используем 443 через Nginx.

### 2.2. Приём событий

`POST /webhooks/telegram/{integration_id}`:

1. Интеграция существует и активна, иначе `404`.
2. Заголовок `X-Telegram-Bot-Api-Secret-Token` совпадает с секретом (сравнение хешей
   через `hmac.compare_digest`), иначе `403`.
3. Тело разбирается как JSON (лимит размера — 1 МБ), берётся `update_id`.
4. `INSERT INTO inbound_events … ON CONFLICT DO NOTHING`; новое событие → задача Celery.
5. Ответ `200` с пустым телом.

Повторная доставка того же `update_id` отбрасывается на шаге 4. Telegram повторяет
доставку, если не получил ответ 2xx (⚠ проверить число попыток).

Обрабатываемые типы:

| Событие | Что делаем |
|---|---|
| `message` с `text` в личном чате | Сообщение клиента или команда |
| `message` с `contact` | Если `contact.user_id` = отправитель — сохраняем телефон как подтверждённый |
| `message` с фото, голосом, стикером | Вежливый ответ, что бот понимает текст; при повторе — предложить сотрудника |
| `callback_query` | Нажатие кнопки → `answerCallbackQuery` сразу, затем действие |
| Групповые чаты, каналы | Игнорируются в MVP (`status = ignored`) |

### 2.3. Команды

| Команда | Действие | ИИ |
|---|---|---|
| `/start` | Приветствие салона, кнопки «Услуги и цены», «Записаться», «Мои записи» | нет |
| `/start staff_<код>` | Привязка Telegram сотрудника к учётной записи (код из панели, одноразовый, 15 мин) | нет |
| `/services` | Список активных услуг с ценами и длительностью из БД | нет |
| `/booking` | Сценарий записи на кнопках: услуга → мастер (или любой) → дата → время → итог → подтверждение | нет |
| `/cancel` | Будущие записи клиента с кнопками «Отменить» → подтверждение | нет |
| `/help` | Что умеет бот, как позвать сотрудника | нет |
| `/admin` | Только для привязанных сотрудников: записи на сегодня, диалоги, ожидающие ответа, ссылка на панель | нет |
| Любой текст | Conversation Manager → ИИ | да |

`/admin` проверяется по `users.telegram_user_id` и `is_active`. Ответ на
`/admin` от клиента ничем не отличается от неизвестной команды — бот не раскрывает, что
такая команда существует.

### 2.4. Клавиатуры

- **Inline-клавиатуры** (`inline_keyboard`, `callback_data`) — выбор услуги, мастера,
  даты, времени, подтверждение и отмена. До 8 кнопок времени в сообщении + «Другие даты».
- **Reply-кнопка «Поделиться номером»** (`request_contact`) — когда для записи нужен
  телефон (`require_phone`). Номер, отправленный так, подтверждён Telegram. Клиент может
  написать номер и текстом — тогда он хранится как неподтверждённый.
- После нажатия кнопки подтверждения кнопки в исходном сообщении убираются
  (`editMessageReplyMarkup`), чтобы нельзя было подтвердить дважды. Повторное нажатие
  всё равно безопасно: `pending_actions` уже не в статусе `pending`.

### 2.5. Отправка и ошибки

- `sendMessage` без разметки (`parse_mode` не задаём): текст ИИ не нужно экранировать,
  и модель не сломает HTML. Сводка записи от backend — тоже простой текст.
- `sendChatAction` `typing` перед ответом ИИ и каждые 4 секунды, пока модель работает.
- Ошибки API Telegram (⚠ проверить коды):
  - `429` — ждём `parameters.retry_after` секунд;
  - `403` (пользователь заблокировал бота) — `is_reachable = false`, без повторов;
  - `400` (чат не найден, слишком длинный текст) — без повторов, ошибка в журнал;
  - `5xx` и сетевые ошибки — повтор.
- Лимиты рассылок (⚠ проверить): не больше ~1 сообщения в секунду в один чат и ~30 в
  секунду всего на бота.

### 2.6. Сотрудники в Telegram

- Привязка: сотрудник в панели нажимает «Подключить Telegram», получает ссылку
  `https://t.me/<бот>?start=staff_<код>`, бот сохраняет его `telegram_user_id`.
- Оповещения сотрудникам: клиент просит человека, новая запись (по настройке), ошибка
  интеграции. Отвечает сотрудник клиенту в панели (в MVP — не из Telegram).

### 2.7. Ограничения Telegram, важные для продукта

- Бот не может первым написать человеку, который ни разу не запускал бота. Напоминания
  и рассылки уходят только клиентам, у которых есть диалог в этом канале.
- Номер телефона бот получает только если клиент сам поделился контактом.

## 3. ВКонтакте (этап 7)

### 3.1. Подключение сообщества

1. Владелец создаёт ключ доступа сообщества с правами на сообщения и управление,
   включает сообщения сообщества и возможности ботов.
2. В панели вводит ID сообщества, ключ доступа и придумывает секретный ключ.
3. Backend показывает адрес сервера `https://<домен>/webhooks/vk/<integration_id>`.
   Владелец добавляет его в «Callback API» сообщества, указывает секретный ключ, версию
   API, включает событие «Входящее сообщение» (и `message_event` для callback-кнопок).
4. Строку подтверждения из настроек Callback API владелец вводит в панели (или
   backend получает её методом `groups.getCallbackConfirmationCode` — ⚠ проверить права).

### 3.2. Приём событий

`POST /webhooks/vk/{integration_id}`:

1. Интеграция существует; `group_id` в теле совпадает с сообществом интеграции.
2. `type = "confirmation"` → ответ — строка подтверждения (обычный текст).
3. Поле `secret` совпадает с секретным ключом интеграции (сравнение хешей), иначе `403`.
4. Дедупликация по `event_id` (⚠ проверить, что поле есть в выбранной версии API) →
   `inbound_events` → задача Celery.
5. Ответ — строка `ok`. Если VK не получит `ok`, он повторит доставку
   (⚠ проверить число повторов и таймаут).

Обрабатываемые события: `message_new` (текст, payload кнопок-сообщений),
`message_event` (callback-кнопки — ответ через `messages.sendMessageEventAnswer`).
В беседах (`peer_id ≥ 2000000000`) MVP не работает.

### 3.3. Отправка и клавиатуры

- `messages.send` с `peer_id`, `message`, `random_id`. `random_id` для исходящего
  сообщения детерминирован (из ID строки `messages`/`notifications`), поэтому повтор
  отправки после сбоя не создаёт дубль (⚠ проверить окно дедупликации VK).
- Клавиатура — параметр `keyboard` (JSON): `inline: true`, кнопки `callback` с
  `payload` (⚠ проверить лимит длины payload) — тот же `ButtonAction`, что и в Telegram.
- Кнопки «Поделиться номером» в VK нет: телефон клиент пишет текстом.
- Ограничение частоты вызовов API для ключа сообщества (⚠ проверить, ориентир —
  20 запросов в секунду).
- Ошибки: «нет прав писать пользователю» → `is_reachable = false`; «слишком много
  запросов» → повтор с паузой; остальное — журнал и ограниченные повторы.

### 3.4. Отличия VK, учтённые в архитектуре

| Вопрос | Telegram | VK |
|---|---|---|
| Получение | webhook + секретный заголовок | Callback API + `secret` в теле + confirmation |
| Ответ серверу | `200` | строка `ok` |
| Дедупликация | `update_id` | `event_id` |
| Кнопки | `callback_data` ≤ 64 байт | `payload` callback-кнопок |
| Телефон | кнопка `request_contact` | только текстом |
| Защита от дублей при отправке | нет — повторяем осторожно | `random_id` |

Всё остальное (Conversation Manager, ИИ, запись, уведомления) общее.
